# OPPO Mac 自动同步需求与方案

2026-10-12：用户要求实现可运行 Mac 自动同步 App，含 OPPO 登录、新增原图下载、增量、去重、失败重试、导入 iCloud 照片。

用户选择：首次完整扫描仅建立基线，不导入历史照片。后续通过账号范围内资产 ID 与版本判断新增或修改，不以拍摄日期过滤；定期全量元数据扫描避免遗漏补传的旧照片。

技术：Swift/AppKit/SwiftUI + WKWebView 持久化官方登录会话。用户直接在官方网页完成账号、短信或扫码验证。网页适配器复用官方页面签名与加密逻辑，不导出凭据。保留单一浏览器会话，串行文件下载，经完整大小/图像格式/像素/SHA-256 校验后交给 PhotoKit 文件接口导入系统照片图库。

台账使用原子写入 JSON 与进程互斥锁；按账号、源 ID、内容版本存储任务，内容哈希跨资产去重；PhotoKit 导入前持久化 placeholder ID，异常恢复先查图库。已有图库候选以原文件名匹配并比对原片哈希，不把同名当重复。失败退避重试，达到上限需手动重试；会话失效暂停并提示登录。保留已验证下载缓存，第一版不自动删除源照片或原片。

普通 JPEG/HEIC/PNG 静态照片首版纳入；实况、视频、RAW 等不静默拆分或转换，显示暂不支持。默认应用运行时每 15 分钟扫描，关闭窗口仍在菜单栏运行，退出 App 停止；不自动设置开机启动。

验收：Swift 构建、核心状态机/基线事务/去重/重试/崩溃恢复测试；适配器模拟分页与错误测试；真实 OPPO 网页只读清单与已有样本下载验证；Mac App 官方登录与 PhotoKit 权限需本人完成。明确本地导入成功不代表逐项 iCloud 同步已完成。

这是新建本地项目，无远端或工单；采用本地 feature 分支，命名 issue_0 仅是本地工作流占位，不创建外部 issue/PR，不提交推送。独立 review 使用 qqdev-flow 要求的子 agent。

## 2026-10-12 检查效率优化

目标：保持原图下载／去重／历史基线行为，减少无变化时对 6,395 项清单的遍历。现有每轮完整读取约 64 批元数据。

方案：建立持久化的账号隔离检查点（上次完整扫描的总数、首批资产版本指纹、完成时间）。常规扫描先取最新总数和第一批（当前服务通常 100 项）；总数与首批相同、完整核对距今未满 24 小时且当前账号无待处理任务时，结束轻量检查。首次升级／新账号／总数或首批变化／重试任务／每日兜底／手动完整核对均沿现有流程扫描全列表。异常不提交检查点；轻量结果绝不能标记未读取照片已删除或建立历史基线。重试仍采用完整列表确认源，保留保守行为。

边界：总数不变且首批以外发生替换／修改可能要等每日完整核对发现，用户可随时点击“完整核对”。这不是经过验证的服务端增量游标，不以拍摄时间过滤。普通新增导致总数变化，会在下一次常规检查发现。

## 0.3.0 OPPO JPEG 实况转 Live Photo

用户要求阅读本机 MotionPhotoFromiPhotos 并将转换能力直接集成到 OCloudSync。参考其 appended MP4 拆分、MakerApple 17 / MOV content identifier / still-image-time、音轨保留与 PhotoKit pairedVideo 导入路径，不调用其现有已授权 helper、不修改来源项目或图库数据库。

实现：仅新增 OPPO JPEG 实况支持；保留原始文件并核对长度／像素／SHA-256，原生独立 worker 在本地转换并通过 PHLivePhoto 构造校验后，主 App 一次 PhotoKit 事务导入 photo+pairedVideo。转换具有稳定内容标识、原子缓存清单、超时取消；台账保留原件哈希、配对资源哈希和导入回执。恢复导入须核验 Live Photo 及配对原片，无法确认的导入不会盲目重放。历史基线不变，先前启用后记录为 unsupported 的受支持 JPEG 实况升级为待处理。

封面时间优先 XMP 标记，缺失时采用视频中点并在转换清单标记 fallback；越界时报错。源 JPEG→HEIC、视频→H.264 重新编码，不声称逐字节无损；保留原始复合文件供追溯。普通静态、视频、HEIC 实况各自保持既有范围；失败不会降级导入静态图。

验证：合成带音轨动态 JPEG、解析错误／时间边界／资源配对／台账升级与重试；真实 OPPO 新增样本下载、转换和自动导入，保持用户已授权新增同步范围。只本地构建更新、无 Git 推送、不记录经验。

本轮完成：0.3.0，31 项 Swift + 5 组 JS + 合成 worker 集成测试通过，第三轮独立审查“无问题”。真实 OPPO 新增实况完成导入并在重启后识别已有配对；自动同步15分钟已恢复，6395项历史基线未变。见 LIVEPHOTO.md。

## 0.5.1 实况 GPS 舍入兼容（2026-10-13）

用户反馈多张实况报 `Location metadata changed`。本机失败样本逐字段比对确认，JPEG→HEIC 经度或纬度存在约 1.67e-6 度舍入差异，其余字段除既有允许省略的 ProcessingMethod 外均一致。原来 GPS 字典逐字段完全相等，导致这些转换被误拒绝。

方案：只为 Latitude／Longitude 的有限数值设置 2e-6 度绝对误差上限（单轴约 0.23 米以内），坐标范围、字段缺失、南北／东西方向和其他 GPS 字段继续严格检查。错误指出字段而不输出位置数值。保留原文件、哈希、内容标识、导入回执与基线；不更改已有成功导入，不直接修改台账。先补舍入、超限、缺失、方向、非法数值单测及带非整齐坐标的合成转换回归，再修复、完整 CI、独立审查和真实缓存转换验证。更新 0.5.1 后通过正常重试入口恢复用户已选择的失败任务；不新增历史选择，不记录经验。

本轮修复验证：0.5.1 已本地更新，61 项 Swift 测试及全部本地 CI 回归通过，第一轮独立审查“无问题”。46 个真实失败缓存全部通过新版转换及 Apple Live Photo 配对校验。旧转换器在同类合成高精度 GPS 样本上失败，新版通过；未改写原文件、台账或既有导入回执。代码以独立修复 PR 交付。

## 0.6.0 导入日期与已有图库日期修正（2026-10-13）
