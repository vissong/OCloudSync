# 队列与原文件缓存清理

## 需求与方案

- 导入队列增加“清空全部队列”，经确认取消剩余任务并移除所有批次；保留台账、历史基线、导入回执和查重信息。同一版本不会被自动扫描或“重试失败”重新加入；用户仍可按时间重新选择。
- 未确认的 PhotoKit 提交保留原状态与回执。重新选择时先核对原提交，不重置为全新导入。
- 同步概览显示缓存文件数、文件大小及估算磁盘占用，支持刷新和“一键清空缓存”。范围仅为 originals 内原文件、部分下载与转换副本，不包括台账、账号会话、回执或照片图库。
- 同步运行时禁止清理，需先停止并等待当前操作结束。存在未取消且待确认的图库提交时，暂不允许清空缓存；先核对或清空队列。已取消任务的核对信息仍保留在台账与回执中。
- 清理使用后台线程；不跟随符号链接。删除部分失败时报告剩余缓存，不显示虚假的成功或零占用。界面确认明确说明未完成任务会在以后重新下载。

## 验证计划

队列清空、持久化、扫描/重试不复活、手动重新选择、未确认导入恢复；缓存递归统计、空目录、符号链接、范围边界、清理与重统计；完整 CI、独立审查、安装后确认新控件。真实用户缓存不用于删除测试。

## 验证结果

- 94 项 Swift 单元测试通过；新增清空后编码/解码、扫描、重试、迁移和手动重新选择测试。
- 缓存测试使用独立临时目录，覆盖嵌套转换目录、隐藏 partial、符号链接及根链接拒绝、部分删除失败和再次清理。
- `scripts/test-cleanup.py` 提取实际 AppModel 方法，以临时目录验证运行互斥、统计互斥、台账保存失败不发布清空结果、未确认提交保护、取消队列后可清理以及停止请求下的清理完成等待。
- `scripts/ci.sh` 全部通过，包含现有会话/分页/导入/实况测试、Release 构建、签名检查和 ZIP 校验。
