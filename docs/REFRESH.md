# 0.3.2 下载清单刷新

2026-10-12。用户反馈一张已在官方网页显示的新增实况照片没有进入 App 台账。会话有效，但旧下载快照没有目标文件；离开并重新进入批量下载模式后，首批数据发生变化，App 已识别该照片并完成 Live Photo 转换及导入，没有重试或重复导入。前后总数未变，说明不能仅凭统计总数判断新增是否已被读取。

官方普通相册使用 `/albumpc/v4/dayView`，批量下载使用 `/albumpc/v4/download-mode-data`，官方退出下载模式请求是 `/albumpc/v2/download-mode-exit`。0.3.2 在每轮检查前复用官方客户端结束旧下载模式，等待明确成功后再获取新统计及分页。准备失败不使用旧清单，不更新台账；请求超时进入现有受控页面恢复流程。

分页等待先判断响应序号，新响应尚未到达时返回等待状态，避免 Vue 清空列表或切换标签的中间状态导致误报登录错误。

离线验证：45 项 Swift 测试、22 组桥接测试、25 项会话适配器测试、扫描取消回归及合成 Live Photo 转换均通过。新回归覆盖同总数新照片、退出下载模式等待与失败、403、网络错误、单请求并发、错误来源和不允许的接口地址。Release 构建、架构、签名及 ZIP 校验通过。

真实接口确认：退出下载模式返回 `errorCode: 0`；适配器严格识别此格式，并保留 `code: 200` 格式兼容。空响应、null、false、空字符串及显式失败不会被转为成功。

维护者环境在 App 重启后验证了会话恢复、连续轻量扫描和目标实况去重；已有台账记录保持一致。随后总数变化触发完整核对，原有记录仍保留。这里只确认本机导入与扫描行为，不公开真实相册规模或时间线，也不声称 iCloud 服务端逐项同步完成。
