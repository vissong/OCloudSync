# 0.3.2 下载清单刷新

2026-10-12。用户反馈一张已在官方网页显示的新增实况照片没有进入 App 台账。会话有效，旧清单为 6,396 项；离开并重新进入批量下载模式后，首批数据发生变化，App 已识别该照片并完成 Live Photo 转换及导入，没有重试或重复导入。总数仍为 6,396，说明不能仅凭统计总数判断新增是否已被读取。

官方普通相册使用 `/albumpc/v4/dayView`，批量下载使用 `/albumpc/v4/download-mode-data`，官方退出下载模式请求是 `/albumpc/v2/download-mode-exit`。0.3.2 在每轮检查前复用官方客户端结束旧下载模式，等待明确成功后再获取新统计及分页。准备失败不使用旧清单，不更新台账；请求超时进入现有受控页面恢复流程。

分页等待先判断响应序号，新响应尚未到达时返回等待状态，避免 Vue 清空列表或切换标签的中间状态导致误报登录错误。

离线验证：45 项 Swift 测试、22 组桥接测试、25 项会话适配器测试、扫描取消回归及合成 Live Photo 转换均通过。新回归覆盖同总数新照片、退出下载模式等待与失败、403、网络错误、单请求并发、错误来源和不允许的接口地址。Release 构建、架构、签名及 ZIP 校验通过。

真实接口确认：退出下载模式返回 `errorCode: 0`；适配器严格识别此格式，并保留 `code: 200` 格式兼容。空响应、null、false、空字符串及显式失败不会被转为成功。

最终 0.3.2 App 重启后恢复会话，连续两次扫描各读取首批 100 / 6,396 项、1 批列表，分别约 2.2 秒和 0.5 秒。两轮扫描前后的所有资产记录完全一致，仍为 6,395 项历史基线和 2 项成功导入；目标实况已有 PhotoKit 导入回执，没有重复导入。图库授权可用，自动同步启用，保留用户的 60 分钟间隔。这里只确认导入本机系统图库，iCloud 上传进度由系统管理。

取消、分页超时或唤醒中断时，如果仍在原网页文档中，会将其标为待重载；下一次扫描必须经过现有的退避、重载和会话验证，旧分页回调不能继续供新扫描使用。已跳转的新文档、待登录状态与已有恢复计划保持原状态。新增实际 Swift 扫描方法的离线回归覆盖这些分支。

后续观察到云端总数从 6,396 变为 6,395，刷新触发完整核对：64 批、38.2 秒；所有资产台账记录仍与导入完成后的备份完全一致。包含文档隔离保护的最终构建再次重启后轻量检查通过（100 项、1 批、约 2.1 秒），照片权限和后台续期均正常。
