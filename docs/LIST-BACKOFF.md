# 清单接口延迟重试

## 需求与方案（2026-10-14）

用户反馈清单接口状态 400，要求延迟重试。仅凭业务 400 不能确认限频；官方接口曾在稍后重试时恢复，按可恢复的读取失败处理。

- 对统计和下载清单两个只读接口的业务／HTTP 400、408、429、5xx，使用 5、15、30 秒退避，最多重试三次。传输异常无 HTTP 状态时同样有限重试。
- 每次复用相同页码、快照 ticket 和游标；不提前翻页、不重建快照。登录失效、无效成功响应不重试。
- App 显示错误状态、剩余等待秒数和重试次数；范围导入页同步显示。
- 将等待区分为实际请求和退避阶段，阶段变化才刷新 45 秒无进展超时；每批整体上限六分钟。取消／页面退休后不继续发送请求。
- 原有清单完整性、失败不提交基线和导入记录的规则保持不变。

## 验收

离线测试覆盖延迟序列、成功恢复、重试耗尽、HTTP 与业务错误、登录失效、取消与旧请求失效、等待预算和用户提示。运行完整 CI 并独立审查；构建后检查安装版本。真实服务不能主动制造限频，不能把模拟测试写成真实限频验证。

## 完成结果

- 0.8.1（build 14）实现上述退避和当前流程的状态提示。
- 网页脚本每次调用最多等待五秒且受剩余预算约束；取消会立即结束回调等待，迟到回调只允许一次性完成。超过空闲／总体期限的成功响应不会提交。
- 87 项 Swift 测试、桥接／会话回归、实际原生方法 spy、合成实况转换、release 构建／签名／ZIP 校验全部通过。
- 回归包含连续 400 后最终断网不误报旧状态、已开始等待后取消、46／361 秒迟到成功，以及预览退避后的成功／取消／失败不污染概览提示。
- 第四轮全新独立审查结论“无问题”；先前三轮发现的边界问题均已修复并补充回归。
- 分页参数的真实只读探测见 [BATCH-SIZE.md](BATCH-SIZE.md)。未刻意制造真实服务 400，也未确认其属于限频。
