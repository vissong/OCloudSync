# 清单每批数量验证

2026-10-14，用户希望完整核对从每批 100 改为 1,000。通过本人已登录的官方网页、官方加密客户端，对相同下载快照和第一页进行只读对比。

官方组件的 `pageSize` 原本为 1,000，用于 UI 页码计算；`loadData` 实际传入的字段为 `status`、`index`、`ticket`、`businessType`、`deviceId`，继续读取时还带 `last`。每个 UI 页需要跟随游标分批取完。

| 请求 | 业务状态 | 返回项数 | 页内完成 |
|---|---:|---:|---|
| 官方原始请求 | 200 | 100 | 否 |
| 增加 `pageSize=1000` | 200 | 100 | 否 |
| 增加 `limit=1000` | 200 | 100 | 否 |
| 增加 `size=1000` | 200 | 100 | 否 |

三个试探参数均返回与原请求相同的资产集合，没有扩大批量。当前适配器没有经过验证的 1,000 项请求参数，因此不修改分页计算或假设返回 1,000 项。此结果只证明上述参数无效，不证明服务不存在其他入口。

验证不下载原图、不导入照片、不修改台账；未保存账号、凭据、照片标识、快照 ticket 或签名 URL。当前完整性检查与每批真实进度保持不变。
