# OPPO 实况转换（更新至 0.8.0）

实现基于作者的 MotionPhotoFromiPhotos 转换思路，集成到 OCloudSync 原有下载、查重、重试和 PhotoKit 导入流程。只支持 JPEG 内嵌 mp42 视频的实况容器；其他实况容器暂不支持。0.8.0 起，JPEG 实况转换失败会提取完整静态 JPEG 并导入，保留原始压缩字节、EXIF 与拍摄时间；记录静态回退结果及原因。取消、PhotoKit 写入失败和未知提交不会触发回退。

## 流程与数据

1. 下载完整复合 JPEG，校验云端字节数、静态像素及 SHA-256。
2. 解析 MP4 边界和 XMP 封面时间，独立 worker 生成 HEIC + MOV。
3. 两个资源写入相同的稳定配对标识；MOV 写入 still-image-time，传递音轨和旋转。
4. 检查图像尺寸、拍摄日期、方向、GPS 位置、音轨、时长、配对标识、封面时间与资源哈希，并用 PHLivePhoto 构造验证。
5. 正常导入前按媒体类型、文件名和拍摄秒查重；命中即跳过，也兼容先前转换输出的 HEIC 文件名。回执恢复仍严格核对资源哈希；没有重复时以一次 PhotoKit 事务导入。
6. 保存包含配对清单的导入回执，提交结果不明时先恢复核对。明确没有提交的失败按原退避规则重试。

派生缓存位于 Application Support/OCloudSync/originals/livephotos/ 下，以源 SHA-256 隔离，目录含 live.heic、live.mov、manifest.json。完整缓存复用前再次校验。取消或 180 秒超时后由主 App 等待 worker 退出再删除该次临时目录。原始复合 JPEG 和正式缓存不自动清理。

HEIC/H.264 重新编码不属于字节级无损转换；原文件始终保留。ImageIO 的 HEIC 编码器省略 GPS ProcessingMethod 定位方式标签；0.5.1 起，经纬度允许最多 2e-6 度的编码舍入差异（单轴约 0.23 米以内），须为有效有限数值且不超出经纬度范围，方向、海拔、日期等其余源 GPS 字段仍精确比较。缺失或超限继续中止 Live Photo 转换并尝试静态回退，错误仅指出字段、不输出实际位置。厂商私有元数据不保证保留。没有 XMP 封面时间或其值为 -1 时采用视频中点并记录 usedFallbackTime；无效值、冲突值或越界时报错。

### 0.5.1 舍入回归验证

新增 4 项单测覆盖微小正负舍入、超限坐标变化、GPS 缺失、方向／海拔／日期变化及非法数值；合成 JPEG 使用高精度 EXIF 有理数模拟相机元数据。旧转换器拒绝合成样本，修复后 61 项 Swift 测试和完整 CI（含 Apple Live Photo 配对、缓存复用与损坏恢复）通过。维护者的同类失败缓存样本重新转换后通过 Apple Live Photo 构造验证；该转换验证仅写入独立测试目录，不写入系统图库。

## 初始版本验证（0.3.0）

- 31 项 Swift 测试、5 组网页适配器测试通过。
- 合成两秒音视频样本：封面时间 0.85 秒、有音轨，照片/视频旋转及拍摄元数据检查通过，Apple PHLivePhoto 可构造。
- 合成集成测试覆盖缓存复用、损坏派生缓存重建、截断容器拒绝；取消和超时清理有独立测试。
- 维护者本人新增实况样本完成转换；音轨、XMP 封面时间与 Apple 配对验证通过，原件保留。
- 实机导入完成；照片和 pairedVideo 资源经 PhotoKit 读取复核，系统“照片”显示“实况”标记。
- 退出重开后状态恢复；再次下载／转换／查重识别已有配对，没有重复导入，历史基线保持不变。
- 系统“照片”显示了 iCloud 同步活动，但不作为逐项服务端完成证明。

这些结果证明已验证容器及样本能够转换，不代表所有 OPPO 固件和实况编码变种均已覆盖。已导入表示本机 PhotoKit 验证成功，iCloud 服务端同步由“照片”管理。
