# 相册清单超时修复

## 需求与排查方案

日期范围预览与单文件检查连续出现“OPPO 列表请求超时”。目标是恢复完整清单读取，保留既有基线、导入记录和关闭自动同步的设置。

先核对官方页面请求阶段、回调序号及响应状态；诊断只记录阶段、数值状态码与数量，不保存账号、凭据或照片内容。确定原因后补回归测试，修复实际失败路径；不以放宽完整性检查或延长超时掩盖问题。通过真实日期范围预览验证，不自动导入预览结果。

## 已确认原因与修复

真实扫描在读取第 5 页时，官方 `download-mode-data` 接口返回业务 `code: 400`，没有有效数据。官方页面只在 `code === 200` 且数据有效时调用 `appendRenderList`；原适配器仅等待该成功回调，导致真实失败被延迟并误报为 45 秒超时。稍后重新运行，同一完整清单可以读完，因此本次证据指向可恢复的服务拒绝；尚不能确认具体是限流还是服务端其他临时条件。

0.6.2 复用官方加密客户端，仅对清单计数和分页这两个只读接口观察结果。业务 400 / 408 / 429 / 5xx 最多重试两次，分别等待 1 秒、2 秒，沿用当前页、ticket 和游标；不重新下载或重新导入。持续错误、网络失败或响应结构异常会立即以有界状态返回原生层，403 转为登录失效。取消或页面过期会废弃本轮，阻止已安排的重试继续提交。失败和取消不向官方计数回调交付结果，避免其 catch 自动发起补偿请求；失败状态锁定且每个接口单独计数重试次数。扫描成功后释放受控请求上下文，正常网页操作继续透传；失败或取消后保留废弃标记直到页面重载，阻断仍在等待签名的迟到清单请求。

重试不放宽完整性要求：仍须满足账号一致、总数一致、逐页对应且最终去重数量等于总数，才允许提交检查点／预览。诊断专用代码不随正式版本发布。

## 验证

- 70 项 Swift 测试、40 组桥接回归、25 项会话适配测试通过。新增覆盖重试后成功、持续拒绝、登录失效、计数回调补偿、取消／新页废弃旧重试、异常结构不交付、接口间重试计数重置与扫描后释放上下文。
- 原生轮询与页面退休 spy 测试验证失败及时返回、取消不启动读取、失败旧页不能复用；原有视频、日期修复、范围导入、实况转换测试及构建／签名／ZIP 检查通过。
- 故障恢复分支使用离线响应注入验证；不向真实服务刻意制造 400。
- 独立复审第 3 轮结论为“无问题”；额外使用官方计数函数核对 7 种状态，重试上限和失败锁定通过。

## 0.8.1 后续改进

清单重试延长为 5、15、30 秒，并覆盖 HTTP 层临时错误及传输失败；原生等待预算跟随实际请求阶段，界面显示重试倒计时。详见 [LIST-BACKOFF.md](LIST-BACKOFF.md)。400 的限频原因仍未确认。
