# 代码审查记录

按 qqdev-flow 技能进行独立子 agent 审查。

第一轮发现并修复：

1. WKDownload 取消和迟到回调可能交叉操作下一项任务：增加操作 token、navigation action 绑定；等待取消完成；忽略旧回调。
2. PhotoKit 原片读取没有取消和超时：保留 request ID，增加 120 秒超时与单次 continuation 完成锁。
3. 源列表过滤挡住缓存／导入事务恢复：本地恢复不依赖源记录仍存在；无源无缓存进入明确状态。
4. 取消后遗留 downloading：取消收尾恢复为 pending，可在同一进程重新启用。

第二轮发现并修复：

1. 本地恢复仍等待远端列表成功：在扫描前独立处理缓存和 journal。
2. 同 hash 只尝试第一个历史图库 ID：遍历全部候选，使用仍存在的资产。
3. 查重遗漏隐藏和连拍照片：明确包含这些资源；同时移除会被编辑后尺寸影响的预筛条件。

实测另发现 WKWebView 默认数据存储不能保留所有 OPPO 会话 Cookie，改为官方域 Cookie 经 macOS 钥匙串持久化与恢复。

第三轮全新上下文独立复核：无问题。审查覆盖全部 Sources、Tests、scripts，确认上述修复；Cookie 属性往返检查与 5 组 JavaScript 测试通过。真实登录持久化验收仍以 App 实测结果为准。

## 0.2.0 轻量检查优化

第一轮发现本地坏缓存恢复可能先把任务置为 unavailable，随后轻量扫描忽略它。第一版修复在恢复前后保留需要源核对的账号。

第二轮指出内存标记遇到云列表失败／取消／切换账号时不能跨轮次保留。最终修复将本地恢复与完整云端确认分开：未知源状态、原片缓存不可用时持久化为 pending；只有完整清单确认源版本不存在才 unavailable。移除临时的内存计划对象，增加“坏缓存 → 云列表失败 → 台账重启 → 当轮恢复”回归测试。21 项 Swift 测试及 5 组网页适配器测试通过。

第三轮全新上下文独立复核：无问题。确认未知源状态持久化为 pending，扫描失败、取消、重启、账号切换不会丢失核对意图；轻量检查不修改资产记录、不推进完整核对时间。


## 0.3.0 OPPO 实况转换

第一轮发现并修复：导入前权限／文件校验失败应明确为尚未提交，不能永久卡在 importing；取消时先保存 PhotoKit 明确未提交的失败，再结束任务；取消／超时必须等待 worker 退出后清理本次 stage，避免残留中间文件。增加对应状态与进程清理回归。

真实样本发现 ImageIO HEIC 编码器会省略 GPS ProcessingMethod，改为明确允许该标签省略，其他源 GPS 字段仍严格一致；README 记录元数据与重编码边界。

第二轮发现混合有效／无效或溢出的 XMP 封面时间可能忽略坏值。改为逐个捕获完整属性，校验数量、整数解析与值一致性，补充测试先验证失败再修复。

第三轮全新上下文独立审查完整变更：无问题。31 项 Swift 测试、5 组 JavaScript 测试及真实 release worker 的合成转换、缓存复用、损坏恢复、截断拒绝均通过。真实样本转换与 App 集成状态另见 LIVEPHOTO.md。

## 0.3.1 后台会话续期

第一轮修复：原生续期超时后，不再复用永远 pending 的网页请求槽，改为退避后受控重载；HTTP 404/405/410 等与网络失败分开；台账存储故障停止同步时同时关闭后台续期。下载先取消，再重载，登录／续期失败不会计入文件重试。

第二轮修复：关闭自动同步时，显式手动扫描仍能在退避到期后重载并重新验证；故障恢复的页面导航保留连续失败次数，避免每次都退回 30 秒间隔。新增超时重载隔离、连续故障递增退避与重载条件测试。

真实登录验证修复：官方 2ca3/9ca4 模块把续期路由到地区 API 域名，不能仅允许网页同源；现在精确允许官方生产区域 HTTPS origin 和固定续期路径，拒绝外部域名、非 HTTPS、额外端口与路径。新增相应正反例。37 项 Swift、25 项会话适配器测试与 5 组原有桥接测试通过；真实续期返回 200。

第三轮修复：会话非有效状态时，下一项云下载与列表求值立即以会话错误暂停；下载入口不重载网页，避免沿用已经失效的桥接缓存，页面重置后须重新扫描。官方 HTTP 401 的自动导航保留 unsupported 状态和 300 秒退避，只有显式重新打开登录页才重置该等待。补充连续导航与用户重试组合测试，38 项 Swift 测试通过。

第四轮修复：下载响应 HTTP 403 先发布登录失效，再以会话错误取消，避免被记为普通文件失败；新增页面代际，列表求值返回后和扫描提交前拒绝旧页面响应，页面重置同时取消旧下载。补充下载授权失效与扫描旧响应回归，40 项 Swift 测试通过。

第五轮修复：401 冷却期间的页面加载失败也始终记录重载需求，保留冷却截止时间，到期后重载。补充“401 → 自动导航失败 → 等待冷却 → 成功恢复”的组合回归，41 项 Swift 测试通过。

第六轮修复：官方页面自己的列表请求或鼠标续期也可能导致相册返回首页；记录已完成页面路径，对 module→index 的返回保守等待 300 秒再重新验证，不假定已经观察到 401。正常登录返回首页和用户显式重开仍继续。补充组合导航测试，42 项 Swift 测试通过。后台已排队但尚未运行的续期任务，也在执行前重新检查保活开关。

第七轮修复：页面来源改为在主文档 didCommit 时记录，不等待所有资源 didFinish，覆盖相册启动请求提前返回首页的情况；首页提交后立即保留冷却，页面完成时不绕过等待。补充半加载页面连续回跳的回归，43 项 Swift 测试通过。

第八轮修复：Mac 唤醒不再作为页面导航清除恢复意图；保留首页回跳后的重载标记和退避时间，同时使旧请求与扫描代际失效。有效会话在唤醒后立即重新验证。增加两项唤醒组合回归，45 项 Swift 测试通过。

第九轮修复：已取消但尚未运行的扫描，在任何续期或页面重载之前检查取消；网页求值及续期任务入口也拒绝已取消任务。离线回归提取实际 ensureSession 方法并用续期 spy 验证，修复前可复现停止后仍发送一次请求，修复后为零；正常手动检查仍续期。

第十轮全新上下文独立复核完整变更：无问题。45 项 Swift 测试、25 项会话适配器测试、5 组原有桥接测试及停止时序离线回归均通过。
