# 导入流水线与进度

## 需求

按时间导入大量照片和视频时，全串行处理较慢，概览的未标注分数容易被误认为累计成功数。新版本应重叠下一项下载和当前项处理，明确本轮进度统计，保留去重、日期和回执保障；不打断用户当前正在运行的 0.6.2 导入。

## 方案

- 一个下载准备阶段与一个图库处理阶段并行，最多预取一项；官方网页同时最多一个下载，查重与图库写入依次提交。
- 将下载、原文件校验与本地处理拆开，复用已校验结果；取消时等待预取任务结束再恢复账本，未导入的原文件继续留在缓存。
- 取消每项处理后固定 1.2 秒等待，改为下载请求开始之间至少间隔 1.2 秒，不为本地处理额外空等。
- 显示“本轮队列已处理”，分别统计成功、重复、失败、待处理；不把失败算作成功，也不宣称旧版没有保存的历史范围批次累计数。
- 使用离线可控任务与生产方法 spy 验证阶段重叠、最多两个活动项、图库串行、去重可见性、取消／登录失效／存储失败、缓存恢复和失败计数。

## 验证与进度口径

0.7.0 已接入自动同步和按时间导入。启动后的本地缓存恢复单独显示统计，扫描后的队列显示本轮处理结果；范围导入结束后保留结果，直到开始下一项工作。两阶段统计不可直接当作独立文件的历史累计数。

验证包括单元测试、提取生产方法的离线回归、Live Photo 转换、release 构建、签名与归档校验。覆盖已提交的图库事务在取消后仍完成时的记录保留；未以测试为由写入用户图库。
