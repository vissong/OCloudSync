# OPPO 照片同步（Mac 本地版）

[![Build macOS App](https://github.com/vissong/OCloudSync/actions/workflows/build.yml/badge.svg)](https://github.com/vissong/OCloudSync/actions/workflows/build.yml)

将 OPPO 云相册新增的静态原图、支持的 OPPO 实况照片与独立视频下载到 Mac，经校验与查重后导入系统照片图库，由 macOS 的 iCloud 照片继续上传。**首次扫描只建立历史基线，不导入历史照片或视频。**

## 使用

1. 打开交付目录中的 `OCloudSync.app`（macOS 13+，当前构建适用于 Apple Silicon）。
2. 在「OPPO 登录」中完成官方登录及手机验证。App 使用自己的 WebView 会话；会话 Cookie 保存在本机 macOS 钥匙串，过期时需重新验证。程序不接管密码输入、不保存密码、不复制其他浏览器凭据。
3. 点击「授权照片访问」，允许完整图库访问，用于文件名／拍摄时间查重及导入。
4. 在 Mac「照片」设置中确认当前为系统照片图库且已开启 iCloud 照片。App 不更改这些设置。
5. 点击「启用自动同步」。首次完整扫描成功后记录所有历史资产，此后默认每 15 分钟做轻量检查，出现变化再扫描新增或原文件版本。可改成 5 / 30 / 60 分钟。

0.3.1 在自动同步开启时独立维护会话：原生调度约每 60–75 秒调用一次官方续期接口，与照片扫描间隔分开；成功后将最新 Cookie 保存到钥匙串。页面加载／执行中会等待，网络失败按 30 / 60 / 120 / 240 / 300 秒退避。请求有 40 秒等待上限，每次网页求值有 5 秒上限；网络请求本身沿用官方客户端 30 秒超时。停止自动同步后不再安排后台续期，已发出的官方请求可能正常完成；手动检查仍先验证会话。

检测到官方登录页或明确的 403 失效响应时，界面与菜单栏显示「OPPO 登录已失效」，暂停云端任务，不消耗单张照片重试次数。重新登录后恢复会话检查，并在自动同步开启时继续检查新增照片。接口变化与网络错误使用不同状态；概览显示最近成功验证时间。续期不能绕过 OPPO 的强制登录、风控或最长会话期限；Mac 休眠／App 退出时不续期，唤醒后重新验证，必要时仍需本人登录。

若续期执行超过上限而没有确定结果，先暂停该轮云端操作，按退避时间重载官方页面后重新验证，避免一直复用卡住的请求。重载前会取消尚未完成的下载，保留台账与正式缓存。

关闭窗口后菜单栏仍继续运行；退出 App 或 Mac 休眠时不运行，唤醒后按计时器继续。未配置登录项，重新登录 macOS 后需要打开 App。自动同步开关会随 App 重启保留。

「立即扫描」运行一次常规检查；「完整核对」立即遍历所有元数据；「重试失败任务」重置失败计数并再次处理。在「任务记录」输入唯一文件名，可单独检查原图下载和图库查重，**该检查不会导入照片或修改历史基线**。

0.8.0 新增「导入队列」页面，按批次查看文件清单、累计进度、失败和静态回退结果，支持状态筛选与文件名搜索，重启后继续保留。确认按时间导入时先保存所选清单，再开始处理；升级前未完成的任务归入单独批次。详见 [队列、静态回退与查重](docs/QUEUE-AND-FALLBACK.md)。

0.8.1 遇到清单接口业务／HTTP 400、408、429、5xx 或传输失败时，按 5、15、30 秒延迟重试同一批，最多三次；页面显示重试倒计时，持续失败不提交不完整清单。400 不能单独证明限频，详见 [清单延迟重试](docs/LIST-BACKOFF.md)。

0.7.0 将原文件下载与上一项的转换、查重、入库重叠执行，最多预取一项；图库查重和写入仍依次完成。进度区分本轮已导入、重复、失败、延后和待处理，不再把处理数当成成功数。详见 [导入流水线说明](docs/IMPORT-PIPELINE.md)。

0.6.2 修复清单接口短暂返回错误却被统一显示为超时的问题：当前页遇到业务 400 / 408 / 429 / 5xx 时，最多退避重试两次；持续失败会直接显示接口状态。预览及同步仍要求读取完整清单，失败不会更新基线。详见 [清单超时说明](docs/LIST-TIMEOUT.md)。

## 下载速度（0.6.1）

下载原文件时，同步概览、任务记录和按时间导入页面会显示当前文件名、下载速度、已下载量／文件总量与进度条。每 0.5 秒读取一次实际接收字节，速度按最近约 3 秒计算，自动显示 B/s、KB/s 或 MB/s；准备请求时显示“等待下载…”。照片、实况照片和独立视频均适用。

下载结束、失败或停止后清除速度，每个文件及重试单独计算。缓存命中、原片校验、图库导入和 iCloud 上传不显示下载速度。实现与验证见 [下载速度说明](docs/DOWNLOAD-SPEED.md)。

## 拍摄时间与已有日期修复（0.6.0）

普通照片、实况照片和视频导入时均显式设置图库拍摄时间：优先使用 OPPO 清单的 `datetaken`，缺失时读取照片 EXIF 拍摄日期，再回退到 EXIF 数字化创建日期或视频容器创建日期。原文件提供时区时尊重原值；无时区 EXIF 按 Mac 当前时区解释。下载缓存的文件创建时间不是原始创建时间，不会用于此回退；完全没有可靠日期时保留文件并报告失败。

「任务记录」新增「检查拍摄时间」，只读取本 App 已成功导入且有匹配回执的项目，显示当前日期与目标日期。点击「修复 N 项日期」后保存原日期记录，再原位更新图库拍摄时间，并逐项读回核验。不会重新导入、修改照片／视频原文件或改变历史基线；查重关联到的外部已有资产不在修复范围内。修复中断可重新检查后继续，已正确的日期会跳过。设置过日期后又在照片 App 手动修改的项目、预览后发生日期变化的项目均保留人工改动；旧版首次修复前的人工改动无法自动区分，请先查看差异。

保留系统分类，不新增相簿。PhotoKit 写入的内容由照片 App 分类到「最近保存」；公开接口没有把写入标记为「最近导入」的选项。图库拍摄时间决定按拍摄日期浏览时的位置，与这两个系统分类分开。验证记录见 [日期修复说明](docs/CAPTURE-DATE.md)。

## 按拍摄时间导入（0.5.0）

侧栏「按时间导入」支持补充导入历史照片和视频：选择开始／结束日期与照片／视频类型，点击「预览范围」，再勾选文件并点击「加入队列并导入 N 项」。列表显示拍摄时间、类型、大小和可导入状态，支持全选与取消全选；已导入、已跳过重复和已在任务队列的项目不可重复加入。

日期包含起止日全天，按页面显示的 Mac 当前时区计算。只使用 OPPO 清单的拍摄时间 `datetaken`，缺失或非法时间会单独计数并排除，不以文件名、上传时间或修改时间替代。预览需要完整读取元数据，**不下载或导入，也不改动历史基线**。

点击导入后，会再次核对完整清单、账号和所选资产版本；文件被删除、版本变化、拍摄时间不再属于范围或预览超过 30 分钟时，需重新预览。所选清单和日期范围先作为批次保存，再跳转「导入队列」；仅选择的项目进入去重／缓存／导入／重试流程，未选择的历史记录保持原状。原有自动新增同步规则不受影响。

自动同步关闭时也能手动导入。此页面打开时暂停启动自动任务，已有任务须先完成，后台会话仍按既有设置维护；离开页面后恢复原计划。「停止同步」关闭自动同步并保留已排队的进度，之后可在概览「立即扫描」或「重试失败任务」继续。失败不会自动删除缓存或云端原件。iCloud 上传仍由系统照片管理。

实现与验证说明见 [按时间导入说明](docs/DATE-RANGE.md)。

## 视频转存（0.4.0）

支持 OPPO 云相册中的 MP4、MOV、M4V 独立视频（fileMediaType=3）。按原文件下载并导入系统“照片”图库，不转码；系统继续通过 iCloud 照片上传。文件大小、可播放视频轨道、有效时长和尺寸通过检查后，按同文件名、同拍摄秒和视频类型检查图库是否已存在；导入后的原视频仍会核对哈希。保留文件自身的音轨与元数据，不重新编码。

0.8.2 对 macOS 无法播放的 `hev1` 视频增加无损封装兼容处理：检查 HEVC 配置和全部压缩样本后，生成 `hvc1` 副本，保留原文件。只允许配置完整、参数集不变的单视频轨道；其他情况继续保留失败，不做有损转码。兼容副本经过可播放、时长、尺寸和哈希校验后导入；原文件与副本的哈希分别记录，支持中断恢复，拍摄时间和文件名查重规则保持不变。队列显示“视频已兼容导入”。详见 [HEVC 兼容处理](docs/HEVC-COMPATIBILITY.md)。

升级后首次完整扫描会按账号建立视频历史基线，已存在的视频不导入，此后发现的新增视频沿用现有增量同步、缓存、回执及失败重试。照片历史基线保持不变。视频下载最长等待 2 小时，图库原视频读取最长等待 30 分钟，均支持停止；视频校验在后台进行。macOS 无法读取的视频编码会明确失败并保留文件，不会静默转码或删除云端源文件。

实现与验证边界见 [视频转存说明](docs/VIDEO.md)。

## 同步与去重规则

0.3.2 每轮检查先结束旧的 OPPO 批量下载模式，等服务确认后再读取新清单，避免官方网页可见的新照片被旧下载快照漏掉。准备失败或超时不会使用旧清单，也不更新基线；分页响应未到达时只等待，不把中间状态误报为登录失效。

- 不按拍摄日期判断新增：旧照片今天补传到 OPPO，只要其资产不在历史基线中，也会被识别。
- 日常先读取总数与首批元数据（当前服务通常 100 项），与上次完整扫描的账号隔离检查点比较。总数和首批资产版本一致时，不再遍历后续页面；不会重新下载旧原图或给整个图库重新算哈希。
- 首次升级、首次登录该账号、总数变化、首批资产版本变化、待处理任务、手动“完整核对”均完整读取列表；另外每 24 小时完整核对一次（App 需运行且联网，失败后继续重试）。轻量检查不推进完整核对时间。
- **总数不变且首批以外的旧照片被替换／修改，可能要到每日完整核对才发现。** 可随时手动完整核对；普通新增令总数变化，会在下一轮检查触发全量核对，不以拍摄时间判断新增。
- 按账号、资产 ID、原文件版本提交变化。未完整扫描时不提交基线；轻量检查绝不把没读取的照片当作删除。相册为空时无法可靠获取账号，等待出现文件后再建立基线。失败重试需确认远端源文件时仍使用完整扫描。
- 概览显示最近检查的已读条数、列表批数和耗时；批数仅指同步器请求的清单批次，不包含官方网页的登录、统计、缩略图等额外请求。
- 文件串行下载到 `.part.<原扩展名>`，核对字节数、图像像素或视频轨道／时长／尺寸，再计算 SHA-256；验证通过才进入正式缓存。
- 0.8.0 起，导入前按**相同媒体类型 + 相同文件名（忽略大小写）+ 相同拍摄时间（按秒）**判断重复，命中即跳过；包含隐藏和连拍资源。不同文件名或不同拍摄秒不会仅因内容哈希相同而跳过；同名同时间即使字节不同也按用户规则视为重复。
- 拍摄日期与导入使用同一解析规则：OPPO 拍摄时间优先，缺失时用原文件元数据；绝不使用下载时间。已转换 Live Photo 可匹配对应的 HEIC 文件名。正常查重仅读取图库元数据，不下载 iCloud 原片；不确定提交的恢复仍按回执和资源哈希严格核验。
- PhotoKit 导入前保存本地资产标识 journal，重启先核对已提交的事务和已有缓存；不盲目重放导入。
- 文件失败按 30 / 60 / 120 / 240 / 480 秒退避，最多 6 次尝试；实际执行受 15 秒调度、当前任务和休眠影响。达到上限后需手动重试。列表失败按扫描间隔重试；会话错误由独立的续期退避与重新登录流程处理。
- 云端原文件已删除或版本变化且本机没有可用缓存时，旧任务标记「源文件已移除或更新」，避免持续重扫；有可用缓存或导入 journal 的任务先恢复。

## 范围与状态

0.3.0 支持普通 JPEG、HEIC/HEIF、PNG，以及 **JPEG 内嵌 `mp42` 视频的 OPPO 实况照片**。实况会转换为一组 HEIC + MOV，通过同一标识和封面时间配对，经 Apple Live Photo 校验后作为一张实况照片导入。音轨、图像尺寸、方向、拍摄日期和 GPS 位置字段会校验保留；0.5.1 修复 HEIC 编码的微小经纬度舍入被误判为位置改变，单轴误差上限为 2e-6 度（约 0.23 米以内），其余位置字段仍严格校验。ImageIO 不保留 GPS 定位方式标签，厂商私有元数据也不保证保留。

转换使用 HEIC 和 H.264 重编码，**不是字节级无损转换**；原始复合 JPEG 始终保留。优先读取 XMP 中的封面时间，无有效时间标注（缺失或 -1）时取视频中点，并在转换清单记录回退；无效、冲突或越界的时间会报错。单文件上限 200 MB，视频不超过 60 秒、轨道宽高不超过 8192。其他实况容器、RAW 暂不支持。0.8.0 起，JPEG 实况转换失败时提取完整静态 JPEG 主图，保留压缩数据与 EXIF 原字节，按静态照片导入并显示原因；取消或图库提交失败不触发静态回退。主图也不完整时仍保留失败。

升级时，仅将此前已发现、处于「暂不支持」的新增 JPEG 实况重新排队；历史基线保持不变。正常查重沿用同文件名、同拍摄时间规则，因此符合条件的已有静态照片也会跳过。升级时已耗尽次数的明确实况转换失败会重新排队一次，未知图库提交不会重置。派生资源经验证后复用，损坏则重新转换；若 PhotoKit 提交结果尚未确认，保留回执并先核对图库，避免盲目重传。确认未提交的失败可以退避重试。

转换在独立进程执行，默认 180 秒总超时；取消或超时后先等待子进程结束再清理本次转换临时目录。原图与正式配对缓存不会自动删除。

**「已导入图库」只表示 PhotoKit 导入成功。** App 不把它当成服务端备份完成，不显示伪造的逐项 iCloud 上传百分比；请在系统「照片」中查看 iCloud 同步状态。

OPPO 云端原件不会删除。本机缓存不会自动清理，需预留磁盘空间；iCloud 是否有足够容量由系统管理。不要删除同步台账来「重置失败」，否则重新建立基线可能把尚未同步的新增照片视为历史。

## 数据位置

- 台账、原图缓存、导入 journal：`~/Library/Application Support/OCloudSync/`
- 日期修复前的私有旧／新日期记录：上述目录下 `date-repairs/`，仅本机保存，不提交到仓库。
- WebView 网站数据：macOS 为该 App 管理的 WebKit 数据目录。
- 会话 Cookie：macOS 钥匙串条目 `dev.local.ocloudsync.oppo-session`，不写入普通日志、源码或报告。
- `session-status.json` 仅保存续期状态、时间、成功／失败次数与数值响应码，不含 Cookie、账号或照片信息。
- `ledger.json` 为原子持久化数据，进程锁禁止多个同步进程同时操作；损坏或未知 schema 时停止，不自动覆盖。

OPPO 接口是当前官方网页的私有接口，适配器复用页面的登录、签名和加密逻辑，页面升级可能需要更新程序。第一版本地 ad-hoc 签名，未用 Developer ID 签名和公证，不作为公开分发安装包；重新编译可能触发 macOS 再次要求权限。

## 构建与测试

GitHub Actions 在推送、PR 和手动触发时运行测试、构建 Apple Silicon App，并提供 ZIP 与 SHA-256 校验文件（保留 14 天）。进入 [Actions](https://github.com/vissong/OCloudSync/actions/workflows/build.yml)，打开成功的运行，在 **Artifacts** 中下载。流程和本地复现见 [CI 说明](docs/CI.md)。

依赖 macOS Xcode Command Line Tools / Swift 5.9+；运行 App 无需 Node、Ego 或 Python。Node 仅用于网页适配器的开发测试。

```sh
swift test
node scripts/test-bridge.mjs
node scripts/test-session.mjs
python3 scripts/test-session-cancellation.py
bash scripts/build-app.sh
# 一次执行 CI 全部测试并生成 dist/ 下的安装包
bash scripts/ci.sh
```

构建结果默认位于相邻 `OCloudSync-App/OCloudSync.app`。可通过 `OCLOUD_BUILD_DIR`、`OCLOUD_OUTPUT_DIR` 修改构建与交付目录。源码无第三方包依赖。

关键代码：

- `SyncCore/Ledger.swift`：基线、重试、去重台账、检查点、互斥及下载操作隔离。
- `SyncCore/AlbumScanner.swift`：轻量检查与完整核对切换、分页完整性检查和统计。
- `OCloudSync/WebSession.swift`、`Resources/bridge.js`：官方登录页、分页扫描、签名下载与取消。
- `OCloudSync/CookieVault.swift`：登录会话钥匙串保存与恢复。
- `OCloudSync/PhotoImporter.swift`：原图校验、图库查重与 PhotoKit 导入。
- `OCloudSync/AppModel.swift`：定时调度、任务恢复、状态展示。
- `SyncCore/MotionJPEG.swift`、`LivePhotoWorker/`：容器解析、配对转换及 Apple 校验。
- `OCloudSync/LivePhotoConverter.swift`、`SyncCore/ConversionWorker.swift`：转换进程、缓存与取消清理。

转换实现参考用户提供的本地 `MotionPhotoFromiPhotos` 项目的 `native/make_livephoto_with_audio.swift`；本程序没有使用其图库数据库修改或替换原照片流程。合成样本验证见 `scripts/test-livephoto.py`，不会访问照片图库。

## 队列与缓存清理（0.9.0）

「导入队列 → 清空全部队列」移除全部批次并取消剩余任务，保留已导入记录和查重信息。取消的同一版本文件不会在扫描、重试或重启后自动重新排队；需要时可在「按时间导入」重新选择。

「同步概览 → 原文件缓存」显示文件数量和估算磁盘占用，支持刷新、查看文件和清空缓存。清理覆盖原文件、未完成下载、实况及视频兼容副本；不会删除台账、导入回执、登录状态、OPPO 云端或系统照片图库。未完成任务以后需重新下载，云端已删除的文件无法重新获取。运行中需先停止并等待处理结束；存在未取消且未确认的图库事务时先完成核对或清空队列。清理失败会显示剩余文件，不会把部分失败报告为成功。详见 [清理设计与验证](docs/QUEUE-CACHE-CLEANUP.md)。
